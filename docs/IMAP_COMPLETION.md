# IMAP 收信与同步收尾验收

2026-11-11，A3.8。本单七项代码路径已实现并有脚本 / 本机数据库回归；真实服务端、OAuth 注册应用与吞吐验收未完成。SMTP 发信、POP3、Graph / Gmail API、AI、日历与发布属于独立路线，不把本单完成称为全部 IMAP 标准与服务商差异均已实现。

| 项目 | 实现与入口 | 验证重点 |
| --- | --- | --- |
| 安全连接 | TLS / 强制 STARTTLS、密码 / 仅收信向导、连接重配；Google / Microsoft PKCE / XOAUTH2 | 拒绝明文降级、握手限额、状态回调、SASL 总预算、凭据补偿 / 代次 |
| 大邮件 / 附件 | SIZE 规划、8 MiB 分组、256 KiB 分块、64 MiB 原文上限、512 MiB 缓存、显式附件另存为、原文重取 | 实际 17 MiB 原文、精确偏移 / UID / 长度、断线清理、配额、账号归属 / 路径 |
| 历史与文件夹 | 全部可访问目录独立作用域、UTF-7 显示、导航、可选历史回填 | 同 UID 跨目录不冲突、游标不回退、目录失效保留 |

## 固定安全约束

不以 Message-ID / 解码正文推断跨代身份；弱历史哈希和原文重取观察不自动升级可信来源。恢复仍单候选 1 MiB / 页 10 MiB，不能跳过过大候选；全部 collecting + validating、明确确认重新扫描、generation / revision CAS 保留。最多 128 可访问目录，源目录不可访问时不猜重命名。未知归档不盲目重发 MOVE。

自动同步默认关闭；新建 / 升级真实账号默认全部文件夹，历史默认关闭。自动续页需用户点击，首次只读检查到 located 必停；确认后继续完整重扫才绑定。自动续页不是自动授权恢复 / 发信。

## 未验收及后续独立工作

1. 使用注册的公共 Client ID 和明确授权测试账号验收 Gmail / Microsoft / 通用 IMAP，覆盖真实 TLS / STARTTLS、FLAGS / MOVE、断线 / OAuth 续期 / ACL、服务商限流与目录差异。当前没有真实账号或真实邮件参与测试。
2. 真正五万封以上、稀疏 UID、高延迟 / 持续变化邮箱性能与内存基准；当前协议脚本不等同吞吐压测。UI gateway 仍加载全部分页快照，虚拟列表 / 按视图加载尚未做。
3. 不提供服务器目录 CRUD / 重命名、任意 MOVE、永久删除 / EXPUNGE、keywords / Gmail 原生标签、QRESYNC 或服务器草稿 APPEND。服务器草稿可收取 / 复制为本地草稿，本地草稿不会上传。
4. 完整原文和附件解码仍可能占用最高 64 MiB 原文之外的解析内存，512 MiB 仅缓存配额；不承诺进程 RSS。原文超限明确失败，不跳过 UID。HTML 清洗 / 沙箱、附件预览、发信附件待独立实现。
5. 系统 DNS / TLS 阻塞可能延迟停止，IDLE 仅监测 INBOX；其他目录定时核对。没有跨目录事务快照、歧义副本人工选择、不可访问目录猜测恢复。
6. 原生 WebView、安装包、跨平台凭据 / 文件对话框及发布验收未开展。
