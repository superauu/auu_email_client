# UI 基础与约定

## 设计方向

延续 AuuGit 的桌面工作区：稳定分栏、低干扰表面、细分隔线、克制强调色。邮件客户端阅读区铺满整个窗格，内容从左侧起（不使用网页式居中窄栏），正文优先，账号身份始终可辨认。默认 Paper，提供 Graphite 与 Linen 验证不同风格。

界面布局：62px 顶栏 / 62px 活动栏 / 190–320px 可调导航栏（默认 222px，双击分隔条复位；1250px 以下固定 204px 并隐藏分隔条）/ 280–440px 可调邮件列表（默认 340px，双击复位）/ 自适应阅读区 / 28px 状态栏。1250px 以下适当压缩；960px 以下列表和阅读切换；桌面窗口最小 900×640。浏览器最低支持宽度为 720px，目前不做手机端。

## 样式边界

- 共享结构和状态在 `src/styles/index.css`；未来按 feature 拆分时仍使用同一语义变量。
- 皮肤值来自 `src/themes/contract.ts`，具体值只写在皮肤 JSON；业务 UI 不写十六进制颜色。
- 背景层次使用 canvas / surface / surface-raised；交互使用 surface-hover / surface-selected。
- 文本分 text / text-muted / text-subtle；accent 只用于主要操作、选中和焦点。
- 状态使用 danger / success / warning。账号与标签使用主题相对的 teal / blue / amber 语义类；名称和图标一同表达，不只依靠颜色。
- Tailwind 已接入语义颜色映射，可使用 `bg-background`、`text-foreground`、`border-border`。不混入第三方硬编码配色。
- 模型输出、邮件 HTML、皮肤资源都不能向应用主界面注入 CSS 或 HTML。

## 排版与间距

字体为本地打包 Inter Variable（正文）与 Orbitron Variable（品牌展示字，与 AuuGit 同源；仅用于拉丁品牌词 "AuuMail"，中文回退 Segoe UI / Microsoft YaHei UI / 系统 sans-serif），不从 CDN 请求字体。默认正文 13px、约 2 倍行高；标题 20–27px；列表内容 11–12px；辅助信息 9–11px。重要信息不能仅放在最小字号中。字号可调整和可读性增强是后续任务。

间距采用 4 / 8 / 12 / 16 / 24 / 32px 基础节奏。圆角、控件高度和邮件行高由皮肤规定；布局宽度和交互行为属于应用，不由皮肤重写。长主题、地址和正文必须截断或换行，不得撑破分栏。

## 共享组件

| 组件 | 规则 |
| --- | --- |
| Button | primary / secondary / ghost；默认 type=button；提交必须显式 type=submit |
| Dialog | Radix Portal、遮罩、Title / Description；焦点限制、Esc 与焦点归还；未保存数据由业务拦截 |
| Avatar | 主题相对颜色；配套可见账号或联系人名称 |
| EmptyState | 标题、原因、可选实际操作；区分没有数据与没有搜索结果 |
| ResizeHandle | 指针拖动、左右方向键、Home / End；双击恢复默认宽度；拖拽期间锁定光标并禁止文本选择 |
| ErrorBoundary | 捕获渲染错误，提供恢复入口，不输出可能含邮件内容的错误日志 |

新组件先判断是否可扩展现有基础。共享组件不读取邮箱 store。暂不引入 shadcn 配置或第二套组件体系；当前是直接使用 Radix。

## 状态与交互

- 邮件列表同时覆盖 unread、selected、hover、starred；取消星标后正确更新筛选结果。
- 任何账号切换都保留账号隔离；回复默认使用原账号，撰写页明确展示发件人。
- 搜索为空显示对应空状态；没有内容时不保留上一账号邮件详情。
- 归档是演示会话操作；草稿保存失败保留输入，不清空编辑器。
- 弹窗关闭时未保存修改提示保存或放弃。当前仅保证应用内弹窗关闭保护；浏览器刷新和原生窗口关闭的草稿退出保护尚未实现。
- 未连接的“发送”禁用并说明原因；AI 面板标明未启用，不生成假结果。
- 交互要有成功、失败、等待状态。不要只显示一个没有后续行为的按钮。

快捷键：Ctrl / Cmd + K 聚焦搜索，N 新建邮件（输入框或弹窗内不触发），Esc 关闭弹窗（未保存修改会拦截）。Tab 遍历可操作控件；邮件列表采用原生 button 行为。

## 可访问性与视觉检查

- 图标按钮有 aria-label；选中、展开或切换状态使用 aria-current / aria-pressed 等语义。
- 所有输入有 label；状态和错误使用 status / alert；不要清除全局 focus-visible。
- 保留系统缩放，尊重 reduced-motion 和 forced-colors。新增动效不影响信息可达性。
- 桌面选择策略：应用框架（导航、列表、工具栏、状态栏）不响应文本选择；阅读区、事件视图、关于信息与输入框保留选择。拖动分隔条不得产生选区。
- 新皮肤需检查文本、焦点和主要操作的对比度。当前并未声称通过完整 WCAG 审核。
- UI 改动至少检查 1440×950、900×700，三皮肤 × 明暗模式；检查长正文、空结果、弹窗、键盘操作、横向溢出。
- 截图用于人工检查，行为测试用于验证操作；不把生成截图等同于已经看过截图。
