# 开发路线与验收

## Foundation：本轮

- [x] 工程、Tauri 启动、UI 基础和共享组件。
- [x] 领域契约、演示 gateway、多账号邮件工作区。
- [x] 三款内置皮肤和用户目录扫描的 v1 规范。
- [x] SQLite 初始迁移、FTS5 和错误返回边界。
- [x] 开发文档、AGENTS、检查命令、CI 配置。
- [ ] Microsoft / Google 真实 OAuth 可行性验证：未包含在本轮基础建设中。

## 下一阶段 A：真实数据与通用收发闭环

1. 建立 Rust repositories、系统凭据库服务、桌面 MailGateway 与分页查询 IPC。
2. 完成 IMAP / SMTP TLS 连接验证、账号向导与真实账号持久化。
3. 实现最近邮件增量同步、正文按需读取、多账号队列和断线重试。
4. 真实草稿自动保存、发送队列、附件基础与安全正文渲染。
5. 验收：至少两个真实账号，收信 / 回复 / 发信 / 重启恢复 / 离线阅读；发送结果不明时不重复发送。

## 阶段 B：提供商兼容

Microsoft Graph、Gmail API 与 OAuth 刷新，POP3 / SMTP；在开发初期并行推进应用注册与测试账号配置（这里指工作安排，不要求使用多代理）。保留提供商标签、会话和文件夹原始语义。

验收：每条路径有真实测试账号；重新授权、管理员限制、权限撤销、游标失效、已发送副本和账号隔离都有实际验证。

## 阶段 C：管理与 AI

标签 CRUD、搜索保存、规则、本地事件 / 提醒、ICS；AI 服务配置、摘要、生成回复草稿、提取待办。随后增加日历双向同步。

验收：从邮件整理到事件、生成回复再确认发送形成闭环；无用户授权不上传；AI 文本不能直接执行操作。

## 阶段 D：体验与发布

富文本、附件预览、中文搜索优化、虚拟列表、可调整字号、备份恢复、数据库升级、可访问性审核、macOS / Linux 验证、签名和更新。

验收：大邮箱滚动与同步不卡顿，长期任务可恢复，迁移不丢数据；更新端点和签名属于独立发布配置，不继承 AuuGit 的更新地址。

## 扩展皮肤

在 v1 稳定后再评估资源包、背景图、字体、材质和动效 token；逐步提升 schemaVersion 并提供迁移，不开放任意脚本执行。当前提供的独立目录安装模式应始终保留。
